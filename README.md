# Solana Transfer Extraction — Substreams (Rust)

A Substreams package that extracts native SOL and SPL token transfers from Solana mainnet blocks
**385870151 – 385870156 (inclusive)** and emits one JSON object per transfer:

```json
{"from":"8ryouP8NbMv2EKL9V5xiAq5EEt5hKwnT9DDZHjqgTTWR","to":"DduRAGKHQ5AN1BR3HGUW7ymL8MrTao7sQwZyoYCeSU69","amount":2829556537}
```

## Deliverables

| Path | What |
|---|---|
| `src/lib.rs` | Rust map module `map_transfers` (instruction decoding, account resolution, unit tests) |
| `proto/transfers.proto` | Output model `transfers.v1.Transfers { repeated Transfer { from, to, amount } }` |
| `src/pb/` | Rust bindings generated by `substreams protogen` (prost) |
| `substreams.yaml` | Manifest: Solana block input, map module, protobuf output type, wasm binary |
| `Cargo.toml`, `rust-toolchain.toml` | Crate config (cdylib → `wasm32-unknown-unknown`), pinned toolchain 1.99.1 |
| `artifacts/solana-transfers-v0.1.0.spkg` | Built package |
| `artifacts/transfers.jsonl` | **Final output**: 3974 lines, one `{from, to, amount}` per transfer |
| `artifacts/substreams_output.jsonl` | Raw `substreams run -o jsonl` output (one line per block, includes block number) |
| `.unifiedhiring/run.sh` | Build + run + JSONL conversion in one command |
| `verification/rpc_cross_check.py` | Independent cross-check against Solana JSON-RPC |

## What is extracted

| Program | Instruction | `from` / `to` | `amount` unit |
|---|---|---|---|
| System Program `111…111` | `Transfer` (2), `TransferWithSeed` (11) | funding account / recipient account | lamports |
| SPL Token `Tokenkeg…` and Token-2022 `Tokenz…` | `Transfer` (3), `TransferChecked` (12) | **owner wallet** of source / destination token account | raw token base units (no decimals applied) |

Rules:

- **Successful transactions only.** `Block::transactions()` skips any transaction whose `meta.err` is set (or has no meta).
- **Top-level and inner (CPI) instructions.** Each top-level instruction is visited, then its inner instructions,
  exactly once each. No instruction is decoded twice, so there are no duplicate emissions. Identical lines in the
  output are distinct instructions on chain (for example, a program making the same transfer several times).
- **Address lookup tables.** Account indexes resolve against `account_keys ++ loaded_writable_addresses ++ loaded_readonly_addresses`.
- **Malformed input is skipped, never panics.** Short data, a missing account position, or an out-of-range
  index makes the decoder return `None`. Every lookup is bounds-checked. Unrelated instructions (CreateAccount, MintTo, Burn, …) are ignored.
- **Amounts stay integers** (`u64`). They are never converted to floating point.
- **Owner wallet resolution for SPL** (ambiguity: the task says "wallet address", but SPL instructions move tokens
  between token accounts). Owner comes from the transaction's pre/post token balances. Token accounts created *and*
  closed within the same transaction (e.g. temporary wrapped-SOL accounts) are in neither list, so their owner is
  decoded from the SPL `InitializeAccount` / `InitializeAccount2` / `InitializeAccount3` instruction. If no owner can be
  found, the token account address is used as a fallback. In the six blocks, the fallback was used **0** times
  (4820 of 4820 token-transfer sides resolved to an owner).

## Install (macOS arm64, as verified)

```bash
# Rust (official rustup) + WASM target
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --target wasm32-unknown-unknown
source "$HOME/.cargo/env"

# Substreams CLI, buf (used by `substreams protogen`/`build` for Rust codegen), jq
brew install streamingfast/tap/substreams bufbuild/buf/buf jq
```

Versions used: rustc 1.99.1, substreams CLI 1.26.0, buf 1.75.0, jq 1.7.1, crates `substreams 0.7.6`,
`substreams-solana 0.15.1`, `prost 0.13`.

Get a free API key on [The Graph Market](https://thegraph.market) (some regions are asked to add a card for

## Build and run

```bash
.unifiedhiring/run.sh
```

Equivalent manual steps:

```bash
source .substreams.env
substreams build                                    # cargo build --release --target wasm32 + pack .spkg
substreams info solana-transfers-v0.1.0.spkg        # inspect package
substreams run solana-transfers-v0.1.0.spkg map_transfers \
  -s 385870151 -t 385870157 -o jsonl > artifacts/substreams_output.jsonl
jq -c '.["@data"].transfers[]? | {from, to, amount: (.amount // "0")}' artifacts/substreams_output.jsonl \
  | sed -E 's/"amount":"([0-9]+)"/"amount":\1/' > artifacts/transfers.jsonl
```

Notes:

- `--stop-block` is **exclusive** (`substreams run --help`: "Stop block to end stream at, exclusively"), so `-t 385870157`
  is needed to include block 385870156. The run reports `Processed Blocks: 6 blocks`.
- The network `solana-mainnet-beta` in the manifest lets the CLI pick the endpoint. Override with `-e mainnet.sol.streamingfast.io:443` if needed.
- Protobuf JSON encodes `uint64` as a string and omits zero values. The `jq`/`sed` step turns `"amount":"123"` into
  `"amount":123` textually (no precision loss for values above 2^53) and restores `0` for zero-amount transfers.

Unit tests (native): `cargo test`. They cover SOL + SPL + inner instructions, lookup-table accounts, failed-transaction
skipping, temporary-account owner resolution, and malformed/unrelated instructions.

## Verification report

Cross-checked against Solana JSON-RPC (`api.mainnet-beta.solana.com`, `getBlock` with `encoding=jsonParsed`,
`maxSupportedTransactionVersion=0`). The RPC node's own instruction parser is independent of the Rust decoder. The
script applies the same inclusion rules and compares the transfer **multisets** per block.

```bash
mkdir -p rpc_blocks && for slot in $(seq 385870151 385870156); do
  curl -s --compressed https://api.mainnet-beta.solana.com -H 'Content-Type: application/json' \
    -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"getBlock\",\"params\":[$slot,{\"encoding\":\"jsonParsed\",\"maxSupportedTransactionVersion\":0,\"transactionDetails\":\"full\",\"rewards\":false}]}" \
    -o rpc_blocks/$slot.json; sleep 2; done
python3 verification/rpc_cross_check.py rpc_blocks artifacts/substreams_output.jsonl report.md
```

## Limitations / skipped instructions

- **Not counted as transfers** (by design, they are not transfer instructions): System `CreateAccount`/`CreateAccountWithSeed`
  (lamports funding a new account), `WithdrawNonceAccount`, SPL `MintTo`/`Burn`/`CloseAccount` (lamport refunds), and
  Token-2022 `TransferCheckedWithFee` (extension instruction). None of the latter appeared in successful transactions in
  these blocks.
- Lamport movements done directly by programs (debiting accounts they own, without a System CPI) are balance changes,
  not instructions, so they are not visible as transfers.
- SPL `amount` is in raw base units. The mint's decimals are not applied.
- If a token account were re-initialized with a different owner inside one transaction, the token-balance owner wins.
  This was not observed in these blocks.
- The SPL owner-wallet interpretation is a documented choice. The raw token account addresses are what the instruction
  itself references.
